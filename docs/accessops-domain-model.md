# AccessOps domain model

The additive `ao_*` tables extend the existing Postgres database. The strict Bumps floor-model JSON stays independent. See `apps/api/src/accessops/schema.ts` and `packages/accessops/src/contracts.ts` for authoritative typed contracts.

Organizations own workspaces. Memberships assign roles, sessions bind a user to an authorized workspace, and building/project grants constrain access. Buildings contain levels and canonical spatial entities (rooms, destinations, entrances, corridors, doors, stairs, ramps, lifts and toilets). Names and namespaced external identifiers are aliases, never global identity. Floor-plan links record the exact Bumps project/model version, level, reviewer and reason. Graph versions record reviewed connectivity with explicit evidence references.

Sources describe publisher, URI, license, namespace, trust, freshness seconds and demonstration status. Runs record success/failure/accounting; snapshots retain raw content/format, retrieval time and SHA-256; observations retain normalized original fields, record locator, external ID, observation/effective/verification timestamps, units/method/observer, hash and match result. Match and conflict decisions append reviewer/reason history. Snapshots and observations cannot be updated or deleted through ordinary SQL because immutable triggers reject it.

Identity order is exact contextual namespaced ID → explicit confirmed mapping → normalized name within building and level → unresolved/conflicting candidates. Name-only candidates stay provisional until reviewed. Rooms on different levels never match solely by label. Reviewed graph nodes must agree with canonical building/level context.

`verified`, `reported`, `stale`, `conflicting`, `unknown`, and `simulated` remain distinct. Retrieval is not observation time. Future or expired observations and failed operational refreshes cannot establish current availability. Equivalent physical measurements normalize units. Independent disagreement stays conflicting; source priority only chooses among equivalent values. Human selection must cite current verified evidence and all reviewed candidates; a later conflicting record invalidates the earlier selection. A model cannot promote a reported record to verified.

Investigations persist question, as-of time, source snapshots, graph version, exact observations, hashes, trace, findings, prior-context comparison and provider status. Findings preserve explicit severity rationale, evidence, uncertainties and recommendations. Actions have proposal/approval/in-progress/resolved/rejected transitions, ownership, priority, optional due date and verified resolution evidence. Audit events retain privileged decisions. Scenarios persist isolated changes and evidence. Provider runs distinguish successful execution from unavailable/failed explanation. Durable jobs retain attempts, leases and safe diagnostics.

Database migrations `0001`–`0008` are additive; `0005` and `0007` add tenant integrity, constraints and immutable evidence triggers. Existing unowned Bumps rows are not automatically assigned to a tenant. No migration drops or resets user data. Review legacy duplicate model versions before applying the uniqueness constraint; migration failure requires an operator decision, never automatic deletion.
