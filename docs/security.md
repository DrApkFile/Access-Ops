# Security model and remaining deployment gates

All `/v1/*` and `/projects*` operations require an opaque, database-backed session. Argon2id hashes protect passwords; 32-byte random session tokens are stored as SHA-256 digests, expire after eight hours, and use HttpOnly/SameSite=Lax cookies (Secure in production). Membership and disabled-user state are checked on every request and when a worker claims a job. Login is rate limited; there is no anonymous development bypass or public signup. Admins can change workspace roles and revoke sessions through `PATCH /v1/users/{id}`; the last administrator cannot be demoted.

Roles and resource permissions are cumulative requirements: viewers read; operators execute ordinary workflows; reviewers approve geometry, verified imports, matches, conflicts and actions; source administrators register/import sources; administrators manage workspace membership. Building grants (`read/write/review/manage`) restrict non-admin users within the workspace. Project creator or explicit project grants authorize Bumps resources; a permitted linked building can grant project access. Workspace administrators are trusted for that workspace only. Composite foreign keys prevent cross-tenant relationships; unowned legacy projects remain inaccessible. Read and write isolation, role/session revocation and private file/export routes are integration tested.

Mutations require `x-accessops-request: 1`, reject cross-site requests and enforce configured origins. The Next.js same-origin gateway forwards, rather than invents, CSRF intent. API limits are shared in Postgres, keyed by workspace/user or actual direct-client IP; it does not trust arbitrary forwarded IP headers. Put the API on a private network behind the web gateway in production. A reverse proxy must enforce connection/body/time limits and HTTPS. Multi-instance shared-gateway IP limits may intentionally throttle collectively; tune only with a verified trusted-proxy configuration.

Bodies are bounded to 12 MiB, imports to 2 MiB/5,000 rows, uploads to 10 MiB and 50 million decoded pixels. PNG/PDF contents are validated; unsafe filenames cannot select storage paths. Downloads require the same project authorization. Private uploads live outside web public assets. CSV exports neutralize formulas; HTML reports escape imported text and use a restrictive CSP. Provider endpoints are server configuration, remote HTTP/embedded credentials are rejected, REST registration hosts are allowlisted, and generated SQL uses strict identifiers and bounded validated IDs. No unrestricted SQL endpoint or LLM shell access exists.

Secrets remain server environment/secret-manager values. `.env*`, evidence, encrypted backups and local credentials are ignored by source tracking and Docker context rules. Logs contain request correlation, status, duration and categorical failures, not source bodies or provider responses; redaction covers tokens, passwords and database URLs. AI receives facility evidence only for explicitly consented `ACCESSOPS_PROVIDER_WORKSPACES`. The current deployment-level connection secret arrangement does not implement a per-source credential vault or rotation UI; use a managed secret store and separate deployments where appropriate.

Retention: observations, snapshots, graph versions, findings and audit events are append-only. Operational worker maintenance removes expired sessions/rate-limit buckets/worker heartbeats after a day. There is no ordinary API for deleting immutable evidence or projects; legal erasure/retention expiry requires an approved administrative retention migration and backup expiry procedure. Set a retention policy before importing real personal or sensitive facility data. Avoid personal data and security-sensitive interiors in public demos.

Production gates include managed identity/SSO and account recovery policy as required by the operator, password rotation provisioning, independently reviewed threat model, patched dependencies, real provider-access tests, TLS/persistent storage, disaster recovery rehearsal and load validation. Local controls and passing tests do not establish production readiness. See the delivery document for actual dependency scan findings and unresolved items.

## Integration reuse and model boundaries

Only explicitly configured absolute integration env/credential files are read. Provider keys never become browser variables; database settings from LastMile are not imported. Source connection test results distinguish connectivity from data/reasoning proof. NVIDIA plan parsing requires the same workspace consent as text evidence. Unrecognized serving-model IDs, unsupported claims and malformed citations fail closed. Optional private visible-response diagnostics exclude prompts/hidden reasoning, redact secrets and use 0700/0600 modes; the visible text can still contain sensitive evidence and must follow retention/access policy. Do not publish `.accessops-local`.

Explanation jobs have maxAttempts=1, an intent record before inference and no automatic replay after interruption. This avoids ambiguous duplicate external execution; a user may explicitly request a new run. Ordinary investigations have automatic AI disabled unless opted in. The restored worker now waits for an unavailable database at startup rather than exiting before its first heartbeat; readiness remains false until dependencies recover.

Private browser verification profiles contain session cookies. Keep the entire `.accessops-local` hierarchy private; publish only individually reviewed/redacted artifacts. Interrupted provider request-intent records can require operator reconciliation; do not replay ambiguous external calls automatically.

## Explicit Runtime-to-NVIDIA text fallback

`ACCESSOPS_NVIDIA_TEXT_WORKSPACES` is additional consent for external NVIDIA text, distinct from the existing workspace-wide provider consent. Automatic switches also require `ACCESSOPS_NVIDIA_FALLBACK=true`; empty/denied policy means no NVIDIA request. `meterless/local` blocks cloud routing; pinned provider requests stay pinned. Only bounded configuration/availability/auth failures are fallback eligible. Citation, unsupported-claim, secret-echo and integrity failures stop without provider switching. Attempts/logs identify actual execution, skipped requests, policy denial and sanitized codes. Injected transports are marked mocked. Text policy does not expand or claim successful vision capability.
