# Data sources and contracts

CSV/JSON imports are implemented for independent directories, reviewed topology/audits, measurements and operational records. Use `POST /v1/sources/{id}/preview`, inspect rejected rows and mappings, then commit with the returned `previewHash`; `import-jobs` runs the same import durably. Limits are 2 MiB and 5,000 rows. An explicit `allowPartial` is required when rejected rows exist. Rejected CSV exports neutralize spreadsheet formulas. Raw snapshots are private and source-admin restricted.

Each accepted row uses `recordSchema` in `packages/accessops/src/contracts.ts`: stable `externalId`, building/level context, entity kind/name/external ID and namespace, attribute/value/unit, observation time, method and record locator. Preserve source timezone, effective interval, last verification, reviewer/reason and original field where available. Field mapping maps incoming column names to these contract names. CSV booleans/numbers/arrays must be represented as supported normalized values; inspect preview errors instead of guessing. Verified imports require the authenticated reviewer ID, verification timestamp and review reason.

| Source | Access and useful identifiers | Limits and license |
|---|---|---|
| [MBTA V3 API](https://api-v3.mbta.com/docs/swagger/index.html) | Implemented read-only facilities/alerts connector; facility and stop IDs; station filter; public fetch works without a key at public limits | Facilities identify lift/escalator assets; alerts do not establish building interiors, clear widths or complete connectivity. Preserve timestamps, [MassDOT terms](https://www.mass.gov/info-details/massdot-developers-data-terms-of-use), attribution and API limits. Review terms for deployment. |
| [MBTA accessibility information](https://www.mbta.com/accessibility) | Human reference for supported transport facilities | Not a machine-readable survey of every route; absence of an alert is not restoration proof. |
| [OpenStreetMap](https://wiki.openstreetmap.org/wiki/Key:wheelchair) | Public building/entrance/lift tags and stable OSM IDs, available through documented exports | ODbL attribution/share-alike obligations; varying completeness and survey dates. No implemented OSM connector; import permitted normalized extracts only. Tags are reported observations, not measurements or certification. |
| Facility-owner directories and audit files | CSV/JSON with the owner's room IDs, levels, measurements, method/time and actual permission | Most interior floor plans and maintenance records are private; permission and secure handling required. They cannot be assumed publicly available. |

The live public connector probe fetched six facility records for MBTA Andrew station. This proves API normalization/fetching only. No claim is made that those records establish the synthetic clinic's state. Escalator closures are never converted to lift outages. Failed refreshes preserve history and mark current operational status uncertain; missing alerts do not fabricate restoration.

The reproducible acceptance workflow creates a **synthetic demonstration building, floor-plan PNG, directory, topology review, door measurements and operational observations** via authenticated APIs. Each independent source is labelled `demo:true`, publisher/URI/license are retained, outages/scenarios are labelled, and review assertions are attributable to the demo reviewer. These are not live facility records or independently surveyed dimensions. Fixtures are generated outside production source under private evidence directories and are reproducible through `apps/api/scripts/demo-workflow.ts`.

A real deployment needs facility-owner permission, a reviewed connectivity survey, independent directory and maintenance exports, dated measured clearances, and sponsor-side accessible tables. Do not combine unrelated public stations and private buildings by fuzzy name. Canonical IDs and reviewed aliases must connect records for the same physical asset.
